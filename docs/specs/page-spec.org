#+TITLE: page-spec
#+OPTIONS: ^:{} -:nil

* Purpose
The page a visitor sees is drawn from a page spec the assistant edits, so the assistant can reshape the site through conversation without ever writing HTML or scripts. Part of an experiment to learn how well an agent reshapes a page and what is hard about it.

* Requirements

** Requirement: The page is drawn from the page spec
The page SHALL show exactly what the page spec describes: components, each with an id and a type from the component catalog, arranged by row and column containers, showing data the page spec holds.

*** Scenario: The skeleton on first load
- *WHEN* a visitor opens the site
- *THEN* they see the skeleton page spec drawn: a header area and an empty content area
- *AND* the chat beside it

*** Scenario: An edit appears without a reload
- *WHEN* the assistant adds a card to the page spec during a turn
- *THEN* the card appears on the page without a reload
- *AND* the rest of the page is unchanged

** Requirement: Only catalog types are drawn
A component whose type is not in the component catalog, or whose properties fail that type's validation, SHALL be rejected with a tool error returned to the assistant; the page does not change.

*** Scenario: An unknown type is rejected
- *WHEN* the assistant adds a component of type =map= and =map= is not in the catalog
- *THEN* the tool call fails with an error naming the allowed types
- *AND* the page is unchanged

** Requirement: The first component catalog
The catalog SHALL contain: heading, text, image, card, list, row container, column container, table, chart (line, bar, pie), key-figure tile, form/button.

*** Scenario: Data shown as a chart
- *WHEN* the page spec holds a series fetched from an API
- *AND* the assistant adds a line chart bound to that series
- *THEN* a line chart of the series is drawn

** Requirement: The page spec lasts for the visit only
The page spec SHALL live in the visitor's browser only.

*** Scenario: A reload returns the skeleton
- *WHEN* a visitor who has shaped the page reloads it
- *THEN* they see the skeleton page spec again

** Requirement: Undo the assistant's last turn
Before each assistant turn the page SHALL keep a copy of the page spec; an undo control restores it. One step back only.

*** Scenario: Undo restores the page before the last turn
- *WHEN* the assistant's last turn removed a table the visitor wanted
- *AND* the visitor presses undo
- *THEN* the page spec, and so the page, is as it was before that turn

** Requirement: The renderer is swappable
The page spec and the tools that edit it SHALL NOT depend on the renderer (React in the first build), so a second renderer could draw the same page spec without changing them.
