#+TITLE: agent-loop
#+OPTIONS: ^:{} -:nil

* Purpose
A visitor chats with an assistant that changes the page through tools. The loop is hand-written so its states and mechanics stay visible: learning what is hard about it is the point of the experiment.

* Requirements

** Requirement: One loop runs to completion per visitor message
On a visitor message the loop SHALL call the model with the conversation, run each tool call the model makes, return the results to the model, and repeat until the model ends its turn or an error occurs.

*** Scenario: A turn with a tool call
- *WHEN* the visitor asks "add a heading that says Hello"
- *THEN* the model calls a page-spec tool and the heading appears
- *AND* the tool result goes back to the model and its reply appears in the chat

** Requirement: Visible states
The loop SHALL always be in one named state the page shows: idle, calling the model, running tools, awaiting the visitor, error.

*** Scenario: The visitor sees progress
- *WHEN* a turn fetches data
- *THEN* the chat shows "calling the model", then "running tools" while the fetch runs
- *AND* returns to "awaiting the visitor" when the reply is complete

** Requirement: The visitor can stop a turn
The visitor SHALL be able to cancel a running turn.

*** Scenario: Stopping keeps edits already made
- *WHEN* the visitor stops a turn after the assistant has added a card
- *THEN* the loop stops and the card stays
- *AND* undo removes it

** Requirement: Visitors need nothing but a browser
The owner's server SHALL supply the Claude API key, which never reaches the browser. The server fixes the system prompt and the tool list in its own code and stores no page spec and no conversation between requests. The loop runs in the visitor's browser; the server relays each model request.

*** Scenario: No key in the browser
- *WHEN* a visitor inspects the page and its network traffic
- *THEN* no Claude API key appears

** Requirement: Hand-written, no agent framework
The loop SHALL be written directly over the Anthropic SDK or the Messages API, not over an agent framework.
