## Recommended resolution

Settled as a record correction (code right, D9's count stale). Amended D9 in place to: "The catalog holds the types of page-spec § The first component catalog: heading, text, image, card, list, row, column, table, chart (line, bar, pie), key-figure tile, form and button." The edit drops the count and names form and button as the code does; it removes no promise the code fails to keep (every listed type is in the catalog). Pinned by: test/page-spec.test.ts "sends a visitor message when the visitor presses a button the assistant drew (Scenario: page-spec § A button sends a visitor message)" (button is a catalog type of its own, put, validated and drawn), and "rejects a component of a type the catalog lacks, naming the allowed types, and changes nothing (Scenario: page-spec § An unknown type is rejected)" (the allowed types are the catalog's list). The seam/catalog row names no count and is unchanged, so design-diff.json lists no row for this finding. No scenario in docs/specs/ states the count; the page-spec requirement text "form/button" (not a scenario) lists the same two types and is left as written; intent R6 says "about ten". No test draws a form (D9 already says so); a merged form/button type is not wanted, since D13 gives the two different actions.
