## Why tests missed it

The only validation test is an unknown type ("rejects a component of a type the catalog lacks"); no test sends a prop the catalog does not define, of any name.

## Recommended resolution

In src/page/catalog.ts validateComponent, test prop names with `Object.hasOwn(entry.props, name)` instead of `in`, so every name the entry does not define is refused with the existing error; in src/page/bindings.ts resolveBindings and resolveValue, build the output with `Object.create(null)` or skip a `__proto__` key, so no input key reaches a prototype. Add a page-spec test that a component with an undefined prop (one ordinary name and `constructor`) is refused and the page is unchanged. Related but distinct: hardening entry site-turn.md#2 (component ids named like Object.prototype members, in tools.ts and bindings.ts lookups); its recommended fix (Object.hasOwn on the component map) does not reach this prop-name check.
