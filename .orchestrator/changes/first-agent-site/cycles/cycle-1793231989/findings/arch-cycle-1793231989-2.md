## Why tests missed it

The stop test ("leaves every tool call of a stopped turn answered for the next turn") checks that every tool_use is answered by id, not which code built the answer, and the two constructions agree today.

## Recommended resolution

Severity is high by the role's rule for a second producer of a cited seam's record; the harm when the two drift (a result shape the Messages API refuses) would make every later request of the visit invalid. Today they agree. In src/agent/tools.ts, lift runTool's local builder into one exported function (for example `toolResult(call, content, isError)`) and export a `stoppedResult(call)` built with it; have runTool's two STOPPED_RESULT returns and loop.ts stop() both use `stoppedResult`, and delete the inline construction in stop(). The seam/tool-list row stays as written: its "one place" is the promise, and the code is what changes.
